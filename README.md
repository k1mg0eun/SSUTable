# SSUTable (시연용, 폰 두 대 버전)

숭실대 학생식당 좌석 예약 앱. 제안서(`docs/SSUTable_제안서및아이디어구체화_G1J2.pptx`)와 와이어프레임 S-01~S-09를 그대로 구현했다.
Android(Java), minSdk 26. Firebase Realtime Database로 폰 두 대 이상이 같은 좌석 현황과 같은 시연 시각을 공유한다.
한 폰에서 예약하면 다른 폰의 좌석 지도에 곧바로 반영되고, 같은 자리를 동시에 누르면 한 명만 예약된다.
Firebase 설정 파일이 없으면 예전처럼 폰 한 대 로컬 모드로 돌아간다(아래 "로컬 모드").

## 실행

Android Studio에서 `SSUTable` 폴더를 열고 Run. 또는:

```bash
cd SSUTable && ./gradlew :app:installDebug
```

에뮬레이터나 폰 없이 브라우저에서 보려면 [docs/APPETIZE.md](docs/APPETIZE.md)를 참고한다.

규칙 테스트(JUnit):

```bash
cd SSUTable && ./gradlew :app:testDebugUnitTest
```

## 발표 시연 순서 (설정 → 시연 모드)

1. **시간대별 규칙**: 모드 지정 `자동`, 시각 옮기기 `11:15`, 시간 배속 `10배`. 30초쯤 지나면 홈이 스터디에서 점심 식사로 바뀌고, 예약하면 식권이 함께 나온다.
2. **식권과 자리 함께 예약**: 좌석 탭에서 빈자리를 누르고 예약하기를 누른다. 예약 완료 화면에서 식권을 누르면 QR이 나온다.
3. **도착 확인**: 내 예약 아래 `시연용 위치`를 `밖`으로 바꾸면 [도착]이 꺼지고, `학생회관 안`으로 바꾸면 켜진다.
4. **자동 반납**: 사용 중일 때 `밖`을 누르면 자리 비움으로 바뀌고 30분 카운트다운과 알림이 뜬다. 10배속이면 3분 뒤 "30분 이탈"로 체크아웃된다.
5. **동시 예약 실패**: `다음 예약을 동시 예약 실패로 만들기`를 켜고 예약하면 "방금 다른 학생이 먼저 예약했어요"가 나온다.
6. **운영 종료**: 모드 지정 `종료`.

`모든 데이터 지우고 처음부터`로 권한 안내 화면부터 다시 시작할 수 있다.

## 구조

| 위치 | 하는 일 |
| --- | --- |
| `core/` | 순수 Java 규칙. 시간표(`Schedule`), 예약 상태 변화(`ReservationEngine`), 340석 배치(`SeatLayout`), 다른 학생 시뮬레이션(`OccupancySimulator`, 두 모드 모두 실제 점유가 없는 좌석에 쓴다) |
| `core/FloorMerger`, `SeatClaim` | 서버의 좌석 점유(`SeatClaim`)와 내 예약을 합쳐 좌석 상태를 만든다(진짜 예약 우선, 만료 무시, 내 진행 중 예약의 좌석만 MINE) |
| `core/DemoSettings`, `DemoState` | 시연 설정(시각 기준점, 배속, 모드 지정, 시험기간)의 인터페이스와 값 |
| `core/SeatRepository` | 화면이 데이터에 접근하는 유일한 창구 |
| `data/FirebaseSeatRepository` | 기본 구현. 좌석 점유는 Realtime DB 트랜잭션으로 잡고, 내 예약은 `/reservations/{uid}/current`에 저장 |
| `data/FirebaseDemoSettings` | `/demo`를 듣고 쓰는 공유 시연 설정과 서버 시각 오프셋 |
| `data/SeatClaims`, `ReservationJson` | `/seats` 항목과 예약을 DB에 쓰는 모양으로 바꾸는 변환 |
| `data/LocalSeatRepository`, `LocalDemoSettings` | `google-services.json`이 없을 때만 쓰는 로컬 구현. SharedPreferences에 저장 |
| `data/HistoryStore`, `Prefs` | 이 폰의 이용 기록과 설정 값 저장 |
| `ui/` | 화면. `SeatMapView`가 도면을 직접 그린다 |

## Firebase 설정 (처음 한 번)

이미 만들어 둔 프로젝트: Firebase 프로젝트 ID `ssutable-4746b`, DB 지역 `asia-southeast1`
(`https://ssutable-4746b-default-rtdb.asia-southeast1.firebasedatabase.app`). 새로 만들 때 순서는 다음과 같다.

1. Firebase 콘솔에서 프로젝트를 만든다.
2. Android 앱을 등록한다. 패키지 이름은 `com.g1j2.ssutable`.
3. 내려받은 `google-services.json`을 `app/google-services.json`에 둔다. 이 저장소에는 이미 들어 있어서 받자마자 같은 Firebase에 붙는다.
4. 콘솔 → Authentication → 로그인 방법에서 **익명**을 켠다.
5. 콘솔 → Realtime Database → 데이터베이스 만들기(지역 `asia-southeast1`).
6. 콘솔 → Realtime Database → **규칙**에 저장소의 `database.rules.json` 내용을 통째로 붙여 넣고 **게시**한다.

### 로컬 모드

`app/google-services.json`이 없으면 빌드는 그대로 되고, 앱은 `LocalSeatRepository`를 써서 폰 한 대에서 가짜 학생들로 돌아간다.
설정 화면 연결 상태에는 "로컬 모드(Firebase 설정 없음)"가 보이고 "모든 좌석 예약 초기화" 버튼은 숨겨진다.
파일은 있는데 로그인이나 첫 로드가 안 되면 홈 상단에 "오프라인" 태그가 뜨고 예약은 실패(`ERROR`)한다.

## 폰 두 대 시연 순서

1. 두 폰에 같은 빌드를 설치하고, 설정 화면 연결 상태가 둘 다 "연결됨"인지 본다.
2. 리허설 뒤에는 설정 → "모든 좌석 예약 초기화"로 좌석을 비운다.
3. 폰 A에서 시연 설정(시각 옮기기, 배속, 모드 지정, 시험기간)을 바꾸면 폰 B에도 같이 적용된다. 시연 설정은 모든 폰이 공유한다.
4. 폰 A가 자리를 예약하면 폰 B 좌석 지도에서 그 자리가 남의 자리로 바뀐다.
5. 두 폰이 같은 자리를 거의 동시에 눌러 한 명만 예약되는 것을 보여 준다.
6. 한 폰의 예약을 시간 만료·미도착으로 끝내 자리가 다시 비는 것을 보여 준다.

`모든 데이터 지우고 처음부터`는 내 폰의 정보와 내 예약만 지우고, 다른 폰과 공유하는 시연 설정은 건드리지 않는다.

## 두 폰 확인 체크리스트

- [ ] 한 폰에서 예약하면 2초 안에 다른 폰 좌석 지도에 반영된다.
- [ ] 두 폰이 같은 자리를 동시에 예약하면 한 명만 성공하고 다른 폰에는 실패 안내가 뜬다.
- [ ] 시각·배속·모드 지정을 바꾸면 두 폰이 같은 시각을 보여 준다.
- [ ] 10분 미도착, 시간 만료, 30분 이탈이면 자동 반납되어 자리가 비고 다른 폰에도 반영된다.
- [ ] "모든 좌석 예약 초기화"를 누르면 예약 중이던 폰이 "시연 초기화"(RESET) 화면으로 예약을 끝낸다.
- [ ] 앱을 완전히 종료했다가 다시 켜도 내 예약이 복원된다.
- [ ] 비행기 모드에서는 홈에 "오프라인" 태그가 뜨고 예약하면 `ERROR`가 난다. 끄면 다시 연결된다.
- [ ] 한 폰을 와이파이 끈 채로 켠 뒤 와이파이를 켜면 → 연결됨 + 같은 시계.

## 공개 저장소 위험과 대응

저장소가 공개이고 `app/google-services.json`도 함께 올라가 있다. 그래서 누구나 우리 프로젝트에 익명으로 로그인해 좌석과 시연 설정을 바꿀 수 있다.
`database.rules.json`이 로그인 필수, 본인 uid만 쓰기(`/reservations`, `/users`), 좌석 ID·필드·타입 검사로 범위를 줄이지만, 좌석과 `/demo`는 로그인한 누구나 쓸 수 있다.
수업 시연용이라 이 위험은 받아들인다. 장난이 생기면 콘솔에서 익명 로그인을 잠시 끄거나 프로젝트를 새로 만들어 `google-services.json`을 바꾼다.

## 지금 버전의 한계

- 위치는 실제 GPS가 아니라 시연용 스위치로 판정한다(위치 권한은 실제로 요청함).
- 좌석 배치는 팀이 기억으로 그린 배치(1인석 6줄, 소파 부스 9개, 긴 테이블 4개, 6인 테이블 5개, 기둥, 출입구)에 전체 340석·1인석 43석(숭대시보 기사)을 맞춘 것이다. 가운데 세로 줄의 바 테이블, 오른쪽 아래, 맨 아래 줄은 숫자를 맞추려고 채운 자리라 실제와 다를 수 있다. 고칠 곳은 `core/SeatLayout`이다.
- 좌석 만료는 각 폰이 공유 시각으로 판정한다. 서버가 대신 정리하지 않으므로 모든 폰을 끄면 만료된 점유가 DB에 남는다(다음에 누르는 폰이 덮어쓴다).
- 로그인이 익명이라 앱을 지우고 다시 설치하면 새 사용자가 된다.
- 보안 규칙은 시연 수준이다. 공개 저장소 위험은 위 항목 참고.
